# 故障排除

## UI 无法连接 Core

1. 检查首页旁边的连接状态圆点。
2. 重新启动桌面应用。
3. 在安全软件中允许发往 `127.0.0.1` 的本地回环流量。
4. 如果使用浏览器，请验证完整的
   `?ws=ws://127.0.0.1:<port>` 参数。
5. 确认 UI 和 Core 使用相同的 `advanced` 或 `simple` 配置。

配置不匹配会终止当前浏览器会话的连接。普通网络断开会每两秒重试一次。

## Core 已连接，但灯效或设备仍然缺失

WebSocket 端口会在插件初始化和设备发现完成之前公布。请等待启动消息，
或查询启动状态。警告信息可能会指出失败的阶段。

## 已连接的设备没有出现

- 选择**扫描设备**。
- 重新连接 USB 线缆，并避免使用只能充电的线缆。
- 检查相关控制器插件是否已启用。
- 关闭可能独占设备的软件。
- 在 Windows 上，按照简易 UI 显示的任何 CH340 驱动诊断操作。
- 如果已检测到硬件但验证失败，请检查 Core 日志。

串口/HID 发现与网络设备发现使用不同路径。控制器必须匹配并成功验证候选设备，
它才会成为可见设备。

## Skydimo 因软件冲突暂停了设备

首先关闭提示中指出的应用程序。忽略警告会允许 Skydimo 继续运行，但两个应用
同时写入同一硬件可能导致闪烁、颜色错误，甚至损坏设备。仅当确定硬件支持
安全共享时才使用覆盖选项，随后请重新启用保护。

## 控件没有产生可见效果

- 检查所选 Scope 或设备是否已关闭。
- 检查该设置是否从父级继承。
- 显示完全锁定的设备，并检查 LED 锁所有者。
- 禁用或配置拥有这些锁的扩展。
- 打开设备信息并检查运行状态/FPS。

目前，部分操作失败只会记录在日志中，而不会显示为 Toast 通知。

## 屏幕灯效没有来源或不更新

- 确认灯效声明了屏幕采集支持。
- 选择有效的显示器和区域。
- 降低采样分辨率或 FPS。
- 在 Windows 上尝试其他采集方式。
- 使用桌面应用进行可视化自定义区域选择。
- 在受支持的平台上检查操作系统的屏幕采集权限。

## 音频灯效没有来源或不响应

- 确认灯效声明了音频采集支持。
- 选择默认输出或其他输入/输出设备。
- 重置音频预处理。
- 谨慎提高振幅，并检查平均/归一化参数。
- 确认操作系统能够提供所选音频端点。

## 插件无法安装或加载

- 等待插件初始化完成。
- 在高级模式下使用 `.skyplugin` 安装包。
- 确认安装包包含有效的清单和入口文件。
- 本地开发时，请使用开发插件目录和“刷新”操作。
- 检查 Core 日志中的清单、权限、ABI、入口或页面错误。
- 请记住，简易模式不导入用户插件包。

对于扩展页面，本地 `page` 需要桌面应用。外部 `page_url` 必须使用 HTTP(S)。
如果页面加载失败，请使用**重新加载**，并同时检查 webview 和 Core 日志。

## 配置目录不一致

设置中可以显示独立的 Core 和外壳目录。使用提供的按钮打开这两个目录，
先进行备份，然后确认当前运行的二进制文件/运行配置以哪个目录为准。
Core 正在写入时，请勿复制或删除活动配置文件。

高级和简易运行配置的可变状态会有意存放在不同的配置目录中。

## 收集支持所需信息

请记录：

- 应用版本和运行时配置；
- 设备/控制器/插件 ID；
- 确切的复现步骤；
- 设置中显示的诊断 ID；以及
- 问题发生在高级、简易、桌面还是浏览器模式。

桌面反馈操作会打包经过清理的日志和部分配置。也可以从设置中打开配置/日志位置，
在分享前自行检查内容。
